# 使用指南

本文档详细说明 MediaInfoKeeper 插件的功能、入口位置和每一项设置的作用，供日常配置查阅。更偏底层的实现细节请参考原作者的 [GitHub Wiki](https://github.com/honue/MediaInfoKeeper/wiki)。

## 1. 在哪打开

安装并重启 Emby 后，进入 **Emby 控制台 → 插件**，找到 **MediaInfoKeeper**（图标为视频设置图标）点击进入。

插件配置页由以下几个 Tab 组成：

| Tab | 说明 |
|---|---|
| 主页（默认页） | 总开关、入库处理范围、手动与定时工具、插件处理状态、版本信息 |
| 媒体信息 | MediaInfo 提取、预加载、JSON 存储相关设置 |
| 元数据 | 刮削器（片头片尾数据库、弹幕、豆瓣角色）、TMDB/TVDB 相关设置 |
| 片头片尾 | 片头片尾扫描与打标设置 |
| 增强功能 | 搜索增强、直连、深度删除、通知、多版本合并、UI 优化等杂项功能 |
| 网络代理 | 本地发现地址、代理服务器、TMDB 反代地址 |
| Debug（仅调试版可见） | 面向开发者的调试功能 |

## 2. 功能总览

- **媒体信息管理**：入库/浏览时自动提取 MediaInfo 并持久化为 JSON，条目丢失时可从 JSON 恢复，避免反复触发 ffprobe。
- **片头片尾**：自动扫描并打标片头/片尾，支持与 IntroDb/TheIntroDb 数据库共享识别结果。
- **元数据增强**：中文搜索优化、TMDB/TVDB 补充设置、弹幕与豆瓣角色刮削。
- **strm 直连**：视频/音乐 strm 文件可直接跳转真实地址播放，减少中转。
- **多版本合并**：电影/剧集多版本自动合并显示。
- **网络代理**：为 Emby 的元数据请求提供代理与 TMDB 反代能力。
- **手动与定时工具**：可更新插件、刷新最近入库的元数据、备份恢复媒体信息，以及补齐缺失的媒体流、片头片尾标记和视频预览缩略图。

## 3. 核心机制：ffprocess 放行

Emby 原生会在多种场景下调用 `ffprobe`/`ffmpeg`（如扫描入库、刷新元数据），但对 `.strm` 这类网盘直链文件反复调用探测非常低效甚至无法完成。

插件通过 Harmony patch **拦截**所有 Emby 原生的 ffprobe/ffmpeg 调用，默认全部阻止；只有在插件内部**明确需要**执行媒体探测或视频抽帧的场景（如入库提取媒体信息、补齐缺失的媒体信息、补齐视频预览缩略图）才会主动放行。

放行场景参考：

| 场景 | 是否放行 |
|---|---|
| 插件提取 MediaInfo（入库/补齐缺失/浏览详情） | 放行 |
| 补齐视频预览缩略图 | 放行 |
| 普通元数据刷新（如手动点"刷新元数据"） | 默认不放行 |
| 未纳入"入库处理范围"的媒体库入库 | 不放行 |
| 播放时获取播放信息 | 放行 |

**这意味着**：如果某个计划任务/功能依赖 ffprobe/ffmpeg（例如生成缩略图），但对应场景没有被插件放行，该功能会静默失败。详细放行逻辑参考 [Wiki: ffprocess 放行逻辑](https://github.com/honue/MediaInfoKeeper/wiki)。

## 4. 主页设置

- **启用插件**：自动处理总开关；关闭后停止入库等自动处理，但仍可手动执行计划任务。
- **插件处理状态**：显示插件自己的媒体信息、元数据和片头片尾处理队列；点击“刷新状态”获取最新快照。
- **Emby 入库扫描延迟（秒）**：入库事件触发后延迟多久处理，避免文件写入未完成时提前读取。
- **入库处理范围**（点击“配置”）：
  - **入库提取媒体信息**：选择入库时提取媒体信息并写入 JSON 的媒体库；留空不处理任何媒体库。
  - **入库刷新元数据**：选择入库时覆盖刷新元数据和图片的媒体库；留空不处理任何媒体库。
  - **入库扫描片头**：选择新剧集入库时扫描片头片尾的媒体库；留空不处理任何媒体库。
  - 三项都是**留空 = 不处理**，需要主动选择媒体库。
- **手动与定时工具**：点击“立即运行”可执行一次；需要自动运行时，到 **Emby 控制台 → 计划任务 → MediaInfoKeeper** 设置触发时间。有“配置”按钮的工具可单独设置处理范围或参数。

### 手动与定时工具一览

| 工具 | 说明 |
|---|---|
| 检查并更新插件 | 检查所选更新频道；有新版本时安装，重启 Emby 后生效 |
| 刷新最近入库的元数据 | 按媒体库、入库时间和刷新方式处理元数据；可能修改元数据和图片 |
| 备份已有媒体信息 | 将已存在的媒体流信息保存为 JSON；缺失项跳过 |
| 从备份恢复媒体信息 | 从 JSON 恢复媒体流信息，不重新探测视频 |
| 共享片头片尾标记 | 将本地已有标记提交到已配置的片头数据库 |
| 安全重启 Emby | 没有播放或录制时重启；繁忙时自动延后 |
| 补齐缺失的媒体信息 | 只处理没有媒体流的条目；已有媒体流、元数据和图片不修改。可单独选择媒体库 |
| 补齐缺失的片头片尾标记 | 只扫描没有片头标记的剧集；已有标记不修改。可单独选择媒体库 |
| 补齐缺失的视频预览缩略图 | 按单独选择的媒体库筛选缺少时间轴预览缩略图的视频并逐条强制生成；已有缩略图不重建，也不会刷新影片元数据或普通图片 |

## 5. 媒体信息 Tab

- **启用 MediaInfo 预加载**：Emby 启动/入库时提前加载媒体信息，减少播放前等待。
- **浏览剧集提取媒体信息**：用户在详情页浏览时，若信息缺失则即时提取。
- **条目移除时删除 JSON**：媒体库中条目被删除时，同步清理对应的 MediaInfo JSON 备份。
- **MediaInfo JSON 存储路径模板**：JSON 文件存放路径，默认 `/config/data/MediaInfoKeeper`。
- **提取尝试次数**：单个条目提取失败后的重试次数。
- **提取任务并发数**：同时进行 MediaInfo 提取的并发任务数量。

插件会持续监听 `.strm` 文件内容变更，并按上述 ffprocess 机制阻止/放行 Emby 原生 ffprobe/ffmpeg 调用。

## 6. 元数据 Tab

- **元数据并发数**：元数据刷新任务的最大并发数。
- **阻止非回退语言**：刮削结果语言不在回退语言列表内时阻止写入。
- **刮削器**：可配置的四个数据源，各自有独立弹窗设置：
  - IntroDbProvider / TheIntroDbProvider：片头片尾数据库刮削器。
  - DanmuProvider：弹幕数据源。
  - DoubanRoleProvider：豆瓣演职人员角色刮削。
- **TMDB**：中文回退、备选语言、原语言海报优先、剧集组刮削、缺失剧集增强、本地剧集组文件。
- **TVDB**：中文回退、备选语言。

## 7. 片头片尾 Tab

- **收藏入库时扫描片头**：条目被收藏时触发片头扫描（用于优先处理重要内容）。
- **过滤普通章节**：忽略不含片头/片尾语义的普通章节标记。
- **启用片头打标 / 启用片尾打标**：开启后按选定模式生成片头/片尾标记：
  - `CurrentOnly`：仅标记当前尚未标记的集数。
  - `FillMissing`：补全缺失的标记，不覆盖已有标记。
  - `Overwrite`：覆盖所有已有标记重新生成。
- **片头/片尾最大时长（秒）**：超过该时长的片段不视为片头/片尾。
- **最小正片时长（秒）**：正片时长低于该值时跳过打标（避免误判过短的特典内容）。
- **片头探测并发数 / 指纹时长（分钟）**：声纹指纹计算的并发数和取样时长。
- **打标库范围 / 用户范围**：限定生效的媒体库和用户。

## 8. 增强功能 Tab

按分组说明：

**增强搜索**
- 重建数据库索引：手动触发一次搜索索引重建。
- 启用中文模糊/拼音搜索。
- 搜索时排除原始标题。
- 搜索范围限定。

**Emby 直连**
- 启用 strm 视频/音乐直连：播放 `.strm` 文件时直接跳转真实地址，而非经 Emby 中转；均可单独设置是否跟随 302 重定向、客户端黑名单。

**深度删除**
- 启用深度删除：删除媒体条目时同步清理关联的额外文件（如 strm、元数据缓存等）。

**通知**
- 启用通知增强、接管系统"新增媒体库"通知逻辑。

**刷新调度**
- 接管刷新队列：由插件自身调度元数据刷新任务，替代 Emby 原生调度。

**多版本合并**
- 启用多版本合并、电影版本优先级（文件夹范围/媒体库范围/全局范围）、剧集版本优先级（媒体库范围/全局范围）。

**UI 功能**
- 封面显示优化、背景图回退、音乐封面回退、NFO 增强、隐藏演职人员、拼音排序、总集数显示、播放源名称美化、详情页媒体信息卡片、禁止自动合集、统一媒体库顺序、优化新建媒体库默认设置。

**日志**
- 详细网络请求日志、日志倒序显示、日志来源黑名单。

## 9. 网络代理 Tab

- **自定义本地发现地址**：局域网内 Emby 自动发现广播使用的地址。
- **代理服务器**：启用代理、代理地址、需要走代理的域名列表、忽略证书校验、写入代理环境变量、启用 Gzip。
- **TMDB 替换**：自定义 TMDB API/图片地址、API Key，可配合 [tmdb-proxy](https://github.com/honue/tmdb-proxy) 自建反代使用，解决国内访问 TMDB 困难的问题。

## 10. 入库处理流程（简述）

1. Emby 触发 `ItemAdded` 事件。
2. 判断该条目是否已有媒体信息：已有则跳过；无则尝试从 JSON 备份恢复。
3. JSON 无法恢复时，若该条目所在媒体库在"入库处理范围"内，则放行 ffprobe 提取媒体信息。
4. 等待媒体信息处理队列完成。
5. 按配置异步触发元数据刷新（含片头数据库同步）。

更完整的流程图和时序细节参考 [Wiki: 入库处理流程](https://github.com/honue/MediaInfoKeeper/wiki)。
